## Context

В `WirenboardDevice.create` при сборе `mappableControls` для контрола без маппинга: для обычных устройств — `log.warn("Skipping control …")`; для **`system__*`** — отдельная формулировка про служебное устройство и пропуск немаппируемого контрола (уровень **debug** или **warn** в зависимости от `ignoreSystemControls`).

Требования к конфигу оформлены как **дельта к capability `configuration`**: см. `specs/configuration/spec.md` в этом change.

## Goals / Non-Goals

**Goals:**

- Один булевый флаг в конфиге платформы: **`ignoreSystemControls`**, **по умолчанию `true`**.
- При **`true`** (дефолт): если имя WB-устройства считается «system» по согласованному правилу, сообщение о пропуске из-за отсутствия маппинга — **только `log.debug`**.
- При **`false`**: для system-устройств — снова **`log.warn`** на этом пути. Текст сообщения для `system__*` остаётся **отдельным** (про служебное устройство), как при **`true`**, меняется только уровень (**warn** вместо **debug**), а не формулировка «как у обычных устройств» до флага.

**Non-Goals:**

- Не добавлять маппинг `text` в Matter.
- Не менять уровень логов для других сообщений (`Device has no mappable controls`, ошибки конвертера и т.д.).
- Не вводить произвольные regex в первой версии (достаточно префикса/шаблона, зафиксированного в спеке).

## Decisions

1. **Идентификация «system» устройства**
   Использовать префикс имени устройства **`system__`** (два подчёркивания после `system`), совпадающий с наблюдаемыми именами вроде `system__networks__<uuid>`. Это узко и предсказуемо; при необходимости список правил можно расширить позже.

2. **Имя и семантика флага**
   Ключ **`ignoreSystemControls`**: «игнорировать шум от немаппируемых контролов на служебных устройствах» — т.е. не поднимать их до **warn**, а оставить на **debug**. Значение **`true`** (дефолт) — тихий режим для `system__*`; **`false`** — явно запросить прежнюю болтливость (**warn**) при отладке маппингов.

3. **Прокидывание опции**
   Параметр читается из `PlatformConfig` в `WirenboardPlatform`, передаётся в `WirenboardDevice.create` (новый необязательный аргумент; если опущен в конфиге — **`true`**).

4. **Почему дефолт `true`**
   Типичный сценарий — не засорять лог; исключение (нужны warn по system) задаётся явно.

## Risks / Trade-offs

- [Устройства с именем `system__foo` не из WB system] → маловероятно; при появлении ложных срабатываний расширить правило в отдельном change.
- [Ожидали warn по умолчанию] → выставить **`ignoreSystemControls: false`**.

## Migration Plan

- Обновить плагин; конфиг не обязателен — без ключа действует дефолт **`true`** (тише, чем старый код).
- Нужны **warn** по немаппируемым контролам на `system__*`: **`ignoreSystemControls: false`** (тот же system-специфичный текст, уровень **warn**).

## Open Questions

- Нужны ли дополнительные шаблоны имён (например только `system__networks__*`) — пока достаточно `system__*`.
