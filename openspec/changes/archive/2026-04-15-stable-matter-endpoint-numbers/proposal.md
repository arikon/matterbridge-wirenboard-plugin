## Why

Номера Matter endpoint’ов для bridged-устройств WB сейчас зависят от порядка прихода MQTT meta и обхода `Map`, из‑за чего при перезапуске или изменении порядка discovery номера могут сдвигаться. Это даёт предупреждения `checkEndpointNumbers` в Matterbridge, нестабильную привязку в экосистеме Matter и усложняет отладку. Нужна явная политика **стабильных** номеров относительно структуры устройства.

## What Changes

- Ввести **канонический порядок** построения endpoint’ов внутри одного WB-устройства (термостат и световые композиты — как сейчас по смыслу, остальное — детерминированно, например сортировка по имени контрола), вместо порядка вставки в `Map`.
- По возможности задавать **явные `EndpointNumber`** (или эквивалент в API Matterbridge/Matter.js) при создании `MatterbridgeEndpoint` / дочерних частей, в рамках допустимого диапазона и без коллизий между соседями под агрегатором.
- **Не** требовать отдельной группировки по типу Matter (достаточно одного согласованного порядка слоёв и имён).
- **Вне скоупа на первом этапе:** специальные правила для `system` / `system__*` — не прорабатываются, пока не будет отдельного решения.

## Capabilities

### New Capabilities

- `matter-endpoints`: требования к стабильности и детерминизму номеров Matter endpoint’ов для bridged-устройств WB (включая связь с `uniqueId`/`id` и порядком регистрации).

### Modified Capabilities

- `device-builder`: поведение сборки дерева endpoint’ов (порядок детей, композитов, регистрация) должно соответствовать каноническому порядку и цели стабильных номеров — **требования** к сборке меняются, не только внутренняя реализация.

## Impact

- Код: `src/wirenboardDevice.ts` (порядок `mappableControls`, композиты, создание `MatterbridgeEndpoint`), при необходимости `src/module.ts` (порядок регистрации между устройствами — если войдёт в скоуп).
- Зависимости: API Matterbridge `MatterbridgeEndpoint` (`number` в опциях), поведение `aggregatorNode.add` / Matter.js.
- Тесты: unit-тесты на детерминированный порядок имён/частей; при необходимости сценарии без мока порядка `Map`.
- Пользователи: после обновления возможна **однократная** смена номеров относительно старых инсталляций (**BREAKING** для клиентов, кэширующих endpoint по номеру), если ранее порядок был недетерминирован; следует описать в релиз-нотах.
