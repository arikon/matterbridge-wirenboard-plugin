## Context

Сегодня `endpoint.configUrl` задаётся в `registerWbDevice` как `` `http://${mqttHost}` `` (`module.ts`), где `mqttHost` — из конфига MQTT. Пользовательский запрос: явный **`wirenboardUrl`**, пробрасываемый в `configUrl` без автоматического префикса `http://`.

## Goals / Non-Goals

**Goals:**

- Один необязательный строковый ключ конфига `wirenboardUrl`.
- Непустое значение → использовать как `endpoint.configUrl` **как есть** (после trim), чтобы поддерживать `https://`, нестандартные порты и пути.
- Пустое/отсутствует → прежний fallback `http://<mqttHost>` без **BREAKING** для существующих установок.

**Non-Goals:**

- Валидация URL через URL parser (можно ограничиться trim; неверная строка — ответственность оператора).
- Разные URL для разных WB-устройств (один глобальный URL на процесс плагина, как сейчас один хост MQTT).

## Decisions

| Decision                        | Rationale                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------- |
| Имя ключа **`wirenboardUrl`**   | Ясно указывает на веб-интерфейс Wiren Board, не путается с `mqttHost`.                      |
| Fallback на `http://<mqttHost>` | Сохраняет поведение v1; не требует менять конфиг у всех пользователей.                      |
| Trim пробелов по краям          | Избегает случайных «пустых» значений с пробелами.                                           |
| Не форсировать схему            | Оператор может указать `https://host:443/path`; автодобавление `http://` только в fallback. |

**Альтернативы:** только документировать «ставьте mqttHost = IP контроллера» — уже недостаточно для HTTPS/прокси.

## Risks / Trade-offs

| Risk                             | Mitigation                                          |
| -------------------------------- | --------------------------------------------------- |
| Опечатка в URL ведёт в 404       | Документация + примеры; без жёсткой валидации в v1. |
| Дублирование смысла с `mqttHost` | В README явно: MQTT vs ссылка в UI.                 |

## Migration Plan

Нет миграции данных: новое поле опционально. Существующие конфиги без изменений ведут себя как раньше.
