## Context

- **Upstream:** шаблоны MAP в `wb-mqtt-serial` теперь задают `units` у каналов; в MQTT у контролов появляется `meta.units` согласно [README wb-mqtt-serial](https://github.com/wirenboard/wb-mqtt-serial) (`.../meta/units`).
- **Текущий плагин:** `findMapping` сопоставляет `value` в основном по **`wbType` + `wbUnits`** (`CONTROL_MAPPINGS`). Пустые или неизвестные `units` → нет маппинга.
- **Цель:** закрыть разрыв между строками `units` с MAP и тем, что реально можно выставить в Matter для `electricalSensor` и смежных типов.

## Goals / Non-Goals

**Goals:**

- Покрыть единицы, которые **системно** появились в шаблонах MAP: как минимум **`var`**, **`VA`**, **`kvarh`**, **`kVAh`**, **`Hz`**, **`deg`**, **`ratio`**, **`%`** (THD/HR и аналоги), согласованно с wiki/шаблонами.
- Сохранить существующее поведение для уже поддерживаемых `W`, `V`, `A`, `kWh`, датчиков и т.д.
- Явно зафиксировать в коде/спеке, куда уходит каждая величина (атрибут кластера, масштаб).

**Non-Goals:**

- Менять **wb-mqtt-serial** или контракт MQTT (уже сделано upstream).
- Гарантировать отображение **всех** квадрантных энергий как отдельных независимых счётчиков Matter, если API даёт один набор полей `ElectricalEnergyMeasurement` — допустимы ограничения с документированием.
- Поддержка произвольных пользовательских строк `units` без списка — вне скоупа.

## Decisions

1. **Таблица маппинга по строкам `units`:** расширить `CONTROL_MAPPINGS` новыми строками `wbUnits` (и при необходимости `nameKeywords` только если одна строка `units` неоднозначна — по умолчанию избегать).
2. **Электрическая мощность:**
   - `var` → reactive power (или эквивалент в `ElectricalPowerMeasurement`), масштаб согласовать с существующим `W` (микроватты и т.п., как в текущих конвертерах).
   - `VA` → apparent power.
   - `ratio` для PF → power factor (если атрибут доступен в используемом device type).
     Иначе: зафиксировать в спеке минимальный поднабор и fallback (например только те атрибуты, что уже экспортирует текущий `electricalSensor`).
3. **Энергия:** `kWh` на `cumulativeEnergyImported`. **`kvarh`** / **`kVAh`:** на текущем bridge отдельных reactive/apparent cumulative в том же виде нет → тот же атрибут **`cumulativeEnergyImported`** и та же шкала, **отдельный endpoint на канал** счётчика.
4. **Частота / угол / % (факт реализации):**
   - `Hz` → `ElectricalPowerMeasurement.frequency`, гц в **мГц** (×1000).
   - `deg` (угол фаз MAP) → **прокси** в `rmsCurrent` (миллиградусы в mA-поле); не путать с А.
   - `%` (THD) → **прокси** в `rmsPower` (THD×100); не влажность, если сработали `nameKeywords`; не ppm.

**Альтернатива:** только `nameKeywords` без `units` — отклонена: противоречит появившемуся контракту `meta.units` на MAP.

## Risks / Trade-offs

- **[Risk]** Не все атрибуты электроизмерений включены в дефолтный `electricalSensor` → часть полей Matter может быть недоступна.
  **→ Mitigation:** свериться с `@matter/main` / фактическими `matterClusterIds` в маппинге; при необходимости расширить список кластеров для электрики или завести второй шаблон device type только для расширенного счётчика.

- **[Risk]** Несколько каналов энергии (RP/RN/NP/NN) маппятся на схожие поля Matter.
  **→ Mitigation:** в спеке описать «лучшее усилие» и ограничение по количеству независимых атрибутов.

- **[Risk]** Рост числа endpoint’ов на одном WB-устройстве.
  **→ Mitigation:** ожидаемое поведение после устранения skip; для пользователей — кратко в релиз-нотах.

## Migration Plan

- Релиз плагина **после** обновления шаблонов wb-mqtt-serial на контроллере (иначе `units` могут быть пустыми — старое поведение).
- Откат: откат версии плагина; конфиг пользователя не обязателен.
