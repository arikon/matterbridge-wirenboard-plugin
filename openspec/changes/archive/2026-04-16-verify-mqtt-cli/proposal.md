## Why

Пользователям нужны стабильные **идентификаторы устройств и контролов** Wiren Board для `whiteList` / `blackList` / `deviceOverrides`, а текущий `verify:mqtt` — это dev-скрипт после `npm run build`, с дефолтным брокером из кода и без единого UX с установленным плагином. На контроллере WB Matterbridge и конфиг плагина уже заданы; повторно вводить MQTT-параметры неудобно и ошибкоопасно.

## What Changes

- Вынести логику инвентаризации MQTT (устройства, контролы, канонический порядок, mappable) в **устанавливаемый CLI** с именем команды **`mb-wirenboard-verify-mqtt`**, поставляемый вместе с пакетом плагина (`package.json` → `bin`), чтобы его можно было запускать на WB **без отдельной сборки исходников** (достаточно установленного npm-пакета).
- **Чтение дефолтных параметров MQTT из JSON конфигурации плагина** по **фиксированному упорядоченному списку стандартных путей на контроллере Wiren Board** (первый существующий читаемый файл); **переопределение пути** — опция CLI **`--config <path>`** (и при необходимости env, как в спеке). Явные флаги/переменные для MQTT **перекрывают** значения из выбранного файла.
- Сохранить совместимость с существующим workflow разработчиков: `npm run verify:mqtt` может остаться обёрткой или thin alias на тот же entrypoint.
- Флаг **`--json`**: машиночитаемый вывод (один JSON-документ в stdout) для скриптов; без флага — человекочитаемая сводка как сейчас. Единый **`--help`**; детали — в delta spec.
- **Обогащение вывода конфигом плагина (in-scope ключи):** `devices`, `whiteList`, `blackList`, `deviceOverrides`, `ignoreSystemPrefixedDevices`, `ignoreNetworkPrefixedDevices`, `includeHidden`, `discoveryMode`, **`groupingMode`** — **не сужают** обход MQTT, а добавляют **пометки** (включая влияние **`groupingMode`** на топологию Matter). Прочие ключи (`failsafeCount`, таймауты discovery, `wirenboardUrl`, …) — **v1 не аннотируются**; в README — явное пояснение границ.
- **Помощь в редактировании конфига:** документированный workflow + примеры фрагментов (`whiteList`/`blackList` из id, каркас `deviceOverrides`), опора на **`--json`** и ссылка на **`matterbridge-wirenboard-plugin.schema.json`**; без отдельного мастера генерации конфига.
- **Текстовый вывод:** структура удобная для анализа; **ANSI-метки** (в т.ч. **фоновые цвета** для категорий вроде hidden / overridden / skip) при интерактивном терминале; **`NO_COLOR`** / **`--no-color`**; режим **`--json`** без escape-последовательностей.

## Capabilities

### New Capabilities

- `mb-wirenboard-verify-mqtt`: Устанавливаемая CLI-команда (имя capability совпадает с именем бинарника) для полного обхода брокера WB; **та же исполняемая логика плагина через общие модули**; загрузка конфига по **стандартным путям WB** / **`--config`**; **аннотации** (включая **`groupingMode`**, границы scope) и **README** с workflow авторинга конфига; human-readable (**бейджи**) и **`--json`**; MQTT-переменные с приоритетом над полями из JSON.

### Modified Capabilities

- (нет) — существующие спеки MQTT-клиента и конфигурации не меняют нормативные требования к работе плагина; CLI потребляет те же поля конфига.

## Impact

- `package.json` (`bin`, при необходимости `files`), entrypoint CLI; **рефакторинг `src/`** там, где логика сейчас не экспортируется, чтобы CLI и платформа делили **одни и те же** функции (без дублирования правил); рефакторинг `scripts/real-mqtt-verify.mjs` до тонкой обёртки или удаления.
- **Обязательное** обновление **`README.md`**: пользовательская документация по **`mb-wirenboard-verify-mqtt`** (см. delta spec «README documents the inventory CLI»); `AGENTS.md` — по необходимости для разработчиков.
- Зависимости: без новых тяжёлых пакетов; **максимальный reuse** модулей плагина из `dist/`.
